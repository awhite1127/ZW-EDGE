# RK3562 发布、部署与运维

本文只描述当前正式平台 **RK3562 / AArch64 + systemd**，其他架构和服务管理方式不属于产品交付链。

## 发布机要求

正式发布入口只支持 Linux 发布机，建议使用 x86_64 Linux。需要：

- Bash、CMake、Go 1.22+、Python 3、`file`、`readelf`、`tar`、`sha256sum`；
- RK3562 AArch64 GCC 工具链；
- AArch64 libmosquitto、OpenSSL 运行库与头文件；
- 仅在生成签名包时需要 OpenSSL CLI 和仓库外 Ed25519 私钥。

默认路径可由环境变量覆盖：

```text
RK3562_TOOLCHAIN_ROOT=/home/wu/sdk/kickpi-rk356x/download/rk356x-linux/prebuilts/gcc/linux-x86/aarch64/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu

ARM64_DEPS_ROOT=/home/wu/dl/arm64-deps
```

依赖目录至少提供 `include/mosquitto.h`、`libmosquitto.so.1`、TLS 所需的 `libssl.so.3` 与 `libcrypto.so.3`。发布脚本会验证 ELF64/AArch64、SONAME、动态解释器、RUNPATH、静态 Go 二进制和私有依赖闭包。

## 生成正式发布物

正常发布从仓库根 `VERSION` 读取纯 SemVer：

```sh
CLEAN_BUILD=1 \
BUILD_JOBS=4 \
ARM64_DEPS_ROOT=/home/wu/dl/arm64-deps \
RK3562_TOOLCHAIN_ROOT=/path/to/aarch64-toolchain \
bash scripts/release-arm64-rk3562.sh
```

需要显式构建非默认版本（例如预发布包）时才覆盖版本：

```sh
PACKAGE_VERSION=0.9.1-rc.1 bash scripts/release-arm64-rk3562.sh
```

版本必须是不带 `V` 前缀的纯 SemVer。脚本保证发布目录、tar.gz、`package-info.json.version` 和包内 `VERSION` 一致。

签名能力默认保留但不强制。未设置私钥时生成 unsigned 包，板端默认 `EDGE_UPGRADE_SIGNATURE_POLICY=optional`；设置私钥时生成 Ed25519 签名：

```sh
chmod 600 /secure/edge-release-ed25519.pem

EDGE_RELEASE_SIGNING_KEY=/secure/edge-release-ed25519.pem \
EDGE_RELEASE_SIGNING_KEY_ID=edge-prod-2026 \
bash scripts/release-arm64-rk3562.sh
```

私钥必须在仓库外、不是符号链接，并禁止 group/other 访问。若将板端策略切换为 `required`，必须先完成受控公钥部署和密钥轮换方案。

发布输出：

```text
dist/edge-controller-rk3562-<version>/
├── edge-controller-rk3562-<version>.tar.gz
├── deploy-rk3562.sh
├── deploy-rk3562-display.sh
├── rk3562/display/
│   ├── start-edge-kiosk.sh
│   └── edge-kiosk.desktop
├── SHA256SUMS
└── README.txt
```

传输整个版本目录；部署脚本会读取同目录 `SHA256SUMS`。不要只复制构建目录或单个二进制。

打包阶段会从 `edge-controller` 分离调试符号并对包内 ELF 执行
`strip --strip-unneeded`。符号文件保存在
`dist/debug-symbols/<version>/edge-controller.debug`，只供离线堆栈分析，不需要传到板端。
如需在正式 AArch64 工具链上评估 LTO，可设置
`EDGE_RELEASE_ENABLE_LTO=1`；该开关会强制使用同工具链的 `gcc-ar/gcc-ranlib`，启用前应比较
二进制大小、启动、采集、IPC 和 SQLite smoke 结果。

## 板端要求

- `uname -m` 返回 `aarch64`；
- 使用 systemd，并以 root 执行部署；
- 具备 Bash、Python 3、readelf、sha256sum、tar、ip、ss、curl；
- 8080 端口可用；
- `/opt` 能容纳当前程序、上传包、解压 staging、完整 backup 和安全余量。

## 安装与验证

无屏边缘控制器：

```sh
sudo bash ./deploy-rk3562.sh \
  --package ./edge-controller-rk3562-<version>.tar.gz
```

带屏智能显示终端使用同一后台部署主链，并在公共部署成功后安装 `kickpi` 桌面 Kiosk：

```sh
sudo bash ./deploy-rk3562-display.sh \
  --package ./edge-controller-rk3562-<version>.tar.gz
```

显示版要求系统存在 `kickpi` 用户及 `chromium` 或 `chromium-browser`。Kiosk 安装到：

```text
/home/kickpi/.local/bin/start-edge-kiosk.sh
/home/kickpi/.config/autostart/edge-kiosk.desktop
/home/kickpi/.config/edge-kiosk-chromium/
/home/kickpi/.local/share/edge-kiosk.log
```

重复执行显示版部署只更新启动脚本和本产品 autostart 文件，不删除 Chromium profile 或其他用户 autostart 文件。

部署入口依次完成架构/命令检查、发布哈希、archive 路径安全、metadata/MANIFEST/签名、ELF/动态库、安装、systemd 启动、UDS/HTTP 健康和权限验证。

仅安装并 enable，不立即启动：

```sh
sudo bash ./deploy-rk3562.sh --package ./edge-controller-rk3562-<version>.tar.gz --no-start
```

验证已有安装：

```sh
sudo bash ./deploy-rk3562.sh --verify-only
# 或
sudo /opt/edge-controller/scripts/verify-install.sh
```

`--verify-only` 不接受 package，也不能与 `--no-start` 同用。

## 正式目录

```text
/opt/edge-controller/
├── bin/                         edge-controller / edge-web
├── lib/                         AArch64 私有运行库
├── config/                      现场环境和证书外部配置
├── data/                        三个 SQLite 数据库
├── log/                         controller / web / update / deploy 日志
├── run/                         UDS 与临时运行文件
├── update/
│   ├── upload/                  Web 受限暂存
│   ├── incoming/                manager 接管后的包
│   ├── jobs/                    持久升级任务
│   ├── backup/                  回滚快照
│   └── recovery/                稳定恢复 manager
├── security/                    升级公钥等信任资产
├── systemd/
├── scripts/
├── VERSION
├── package-info.json
├── MANIFEST.sha256
└── MANIFEST.sha256.sig          仅签名包存在
```

重复安装替换程序、私有库、systemd、脚本和 package metadata；保留现场 `config/edge-controller.env`、数据、日志、升级状态、security 和 `/etc/edge-controller/certs`。安装器只补齐现有环境文件缺失的必需键，不覆盖现场值。

## systemd 与环境

长期服务：

```text
edge-upgrade-recovery.service
  -> edge-controller.service
  -> edge-web.service
  -> edge-log-rotator.service

业务服务健康后：edge-upgrade-recovery-verify.service
按任务启动：edge-upgrade@<job>.service
```

三个业务服务都受升级恢复门禁保护。升级处于 backup、switch 或 restore 的不安全中间状态时，不能绕过 recovery manager 启动。

默认环境：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `EDGE_CONTROLLER_DATA_DIR` | `/opt/edge-controller/data` | SQLite 目录 |
| `EDGE_CONTROLLER_LOG_DIR` | `/opt/edge-controller/log` | 日志目录 |
| `EDGE_CONTROLLER_RUN_DIR` | `/opt/edge-controller/run` | UDS/运行文件 |
| `EDGE_CONTROLLER_IPC_SOCK` | `/opt/edge-controller/run/edge-controller.sock` | Go/C++ IPC |
| `EDGE_CONTROLLER_REQUIRE_EXPLICIT_NETWORK_CONFIG` | `1` | 首次网络保护 |
| `EDGE_UPGRADE_SIGNATURE_POLICY` | `optional` | `optional`/`required` |
| `EDGE_UPGRADE_PUBLIC_KEY` | `/opt/edge-controller/security/upgrade-ed25519.pub` | 升级信任公钥 |
| `EDGE_WEB_LISTEN` | `:8080` | Web 监听 |
| `EDGE_LOG_MAX_BYTES` | `5242880` | 单日志阈值 |
| `EDGE_LOG_BACKUPS` | `3` | 备份数量 |
| `EDGE_LOG_ROTATE_INTERVAL_SECONDS` | `60` | 检查周期 |

可选 Web 变量包括 `EDGE_WEB_IPC_TIMEOUT_SECONDS`、`EDGE_WEB_COOKIE_SECURE`、开发态 `EDGE_WEB_TEMPLATE_DIR` 和 `EDGE_WEB_STATIC_DIR`。

首次安装默认保留板端当前 IPv4 和默认路由；只有用户在页面保存并应用网络配置，或导入明确网络配置后，后续启动才恢复产品设置。

## 离线升级

Web 升级流程：

1. 超级管理员在运维页上传正式 tar.gz；
2. Web 写入随机名、受限权限的 upload 文件；
3. root manager 重新校验文件、包、版本、架构、空间和签名；
4. 校验通过后创建 `READY` job；
5. 独立 systemd runner 完成 backup、停服、安装、启动和 health check；
6. 成功提交新版本，失败恢复 backup；
7. 浏览器通过断连观察页等待最终 `SUCCESS` 或 `ROLLED_BACK`。

命令行状态：

```sh
sudo /opt/edge-controller/scripts/update-manager.py status
sudo /opt/edge-controller/scripts/update-manager.py current-version
tail -n 200 /opt/edge-controller/log/update.log
systemctl status 'edge-upgrade@*' edge-upgrade-recovery --no-pager
```

发布如果改变 SQLite schema，必须同时提供经过验证的前向迁移和旧程序回滚策略。现场数据库不能通过删除或重建代替升级设计。

## 日志与健康检查

```sh
systemctl status edge-controller edge-web edge-log-rotator --no-pager
systemctl is-active edge-controller edge-web edge-log-rotator
ss -lx | grep edge-controller.sock
ss -ltn | grep ':8080'
curl -I http://127.0.0.1:8080/
sudo /opt/edge-controller/scripts/rotate-logs.sh --once
sudo /opt/edge-controller/scripts/verify-install.sh
```

耐久测试应持续观察 controller/Web RSS、FD、线程数、SQLite WAL、IPC 延迟与 `server_busy`、采集周期、历史丢弃、MQTT 重连和北向客户端数。

- [ ] MQTT TLS/双向证书/LWT/topic 和 Modbus TCP 北向正确；
- [ ] 网络、时区、NTP、RTC 和诊断导出正确；

- [ ] 24～72 小时故障注入中资源没有持续单调增长。

## 常见故障定位

架构或依赖错误：

```sh
file <artifact>
readelf -hW <artifact>
readelf -dW <libmosquitto.so.1>
```

IPC socket 不存在：

```sh
systemctl status edge-controller --no-pager
tail -n 200 /opt/edge-controller/log/edge-controller.log
ls -l /opt/edge-controller/run/
```

Web 无法访问：

```sh
systemctl status edge-web --no-pager
tail -n 200 /opt/edge-controller/log/edge-web.log
ss -ltn | grep ':8080'
curl -v http://127.0.0.1:8080/
```

数据库版本不兼容时先停服并完整备份，确认目标版本迁移路径；不要直接删除现场数据。
