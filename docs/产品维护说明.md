# Edge Controller 产品维护说明

本文面向交付、售后和现场工程人员，只说明正式 RK3562 产品基线中的账号恢复、配置迁移、恢复出厂、诊断日志和版本确认。部署、升级和验收流程见 [`部署板端解析.md`](部署板端解析.md)。

## 账号维护

当前角色及主要边界：

| 角色 | 主要能力 |
| --- | --- |
| `super_admin` | 全部系统、运维、升级和用户管理能力 |
| `engineer` | 采集、设备类型、告警、Modbus 映射和诊断维护 |
| `operator` | 查看运行数据、确认告警、导出诊断包 |
| `viewer` | 只读查看 |

全新数据库会创建内置 `admin` 和 `user`。出厂密码分别为 `admin123` 和 `user12345`，只能用于受控网络中的首次交付，正式交付前必须修改。全新安装或恢复出厂后，登录页还会提供一次性的“首次部署进入系统”入口；入口被使用后自动关闭，并提示修改密码。

### 遗失超级管理员密码

本地恢复命令只接受已有、已启用的 `super_admin` 账号，不创建账号、不提权，也不修改网络、设备、MQTT、历史、事件或其他业务数据。命令仅允许 Linux `root` 执行，新密码必须为 8～256 字节、不能全为空白、不能使用出厂默认密码，也不能与当前密码相同。

建议停止 Web 和 controller，使旧 Web 会话同步失效，然后执行：

```sh
sudo systemctl stop edge-web edge-controller
sudo /opt/edge-controller/bin/edge-controller --recover-super-admin admin
sudo systemctl start edge-controller edge-web
```

命令会交互式读取并再次确认密码，明文不会作为命令行参数或日志内容出现。SQLite 仍使用现有 WAL、busy timeout 和账号存储逻辑。执行记录写入：

```text
/opt/edge-controller/log/maintenance.log
```

恢复成功后使用新密码登录，并按页面提示再次确认账号密码。如果使用了非默认数据或日志目录，应先按正式环境文件导出对应的 `EDGE_CONTROLLER_DATA_DIR` 和 `EDGE_CONTROLLER_LOG_DIR`。

## 配置迁移

version 4 配置包包含：

- 系统基础设置、时间设置和网络设置；
- MQTT 非密码配置及 TLS 文件路径；
- 通道、主站和自定义设备类型；
- 告警规则；
- Modbus TCP Server 设置和寄存器映射。

配置包不包含：

- MQTT 密码；
- TLS CA、客户端证书和私钥的文件内容；
- Web 用户账号；
- 历史采集数据；
- 历史事件数据；
- 内置设备类型定义，目标版本继续使用自身随软件交付的内置定义。

跨设备导入前必须检查源配置中的网络模式和静态 IP，避免目标设备与源设备地址冲突。导入成功后，采集配置和 Modbus Server 运行态会刷新；导入的网络和时间设置会在设备重启或通过对应设置页手动应用后生效。随后应重新确认目标设备访问地址，并在 MQTT 页面补充密码。TLS 文件路径会迁移，但文件本身需由现场人员预先放入板端，例如：

```text
/etc/edge-controller/certs/
```

证书和私钥的属主、权限及轮换应按客户安全规范管理，不得放入通用配置包或正式基础发布包。

## 恢复出厂范围

| 会清除或恢复默认 | 会保留 |
| --- | --- |
| 系统基础设置 | 当前系统时间不会立即调整 |
| 时间配置（默认设置后续启动时应用） | 网络配置 |
| 通道、主站、设备等采集配置 | 内置及自定义设备类型 |
| MQTT 设置及已保存密码 | 当前软件版本和发布包信息 |
| Modbus TCP Server 设置和寄存器映射 | 板端证书与私钥文件 |
| Web 账号、角色和密码（恢复内置账号） | controller、Web、升级及 Kiosk 日志 |
| 历史采集数据 | 升级状态、任务、备份和 recovery 资料 |
| 历史事件、告警规则和告警运行状态 | `security` 中的升级信任资产 |
| 最近运行错误 | 其他未由恢复逻辑管理的系统级文件 |

恢复完成后会重新开放一次性首次部署管理员入口，并撤销当前 Web 会话。历史事件清理完成后，系统会写入一条新的“执行恢复出厂数据”维护事件，因此事件库最终不一定为空。

## 诊断与日志

| 内容 | 路径或入口 |
| --- | --- |
| controller 日志 | `/opt/edge-controller/log/edge-controller.log` 及 `.1`～`.3` |
| Web 日志 | `/opt/edge-controller/log/edge-web.log` 及 `.1`～`.3` |
| 升级日志 | `/opt/edge-controller/log/update.log` 及 `.1`～`.3` |
| 本地账号恢复记录 | `/opt/edge-controller/log/maintenance.log` |
| 显示终端 Kiosk 日志 | `/home/kickpi/.local/share/edge-kiosk.log` |
| 诊断包 | Web“运维管理 → 现场诊断” |
| 事件导出 | Web“事件告警 → 导出” |

诊断包使用固定白名单，包含历史事件 CSV、运行快照、安装 `VERSION`、`package-info.json`、持久化升级状态以及 controller/Web/update 日志。controller 不可用时，静态版本和升级资料仍可由 edge-web 读取。诊断包不包含数据库原文件、MQTT 明文密码、证书或私钥内容。

显示终端日志不由 edge-web 跨用户自动读取。现场可使用 root 收集：

```sh
sudo tail -n 300 /home/kickpi/.local/share/edge-kiosk.log
sudo cp -- /home/kickpi/.local/share/edge-kiosk.log /tmp/edge-kiosk.log
```

## 软件版本确认

- 日常巡检：系统概览中的“软件版本”；
- controller/Web 启动：分别查看 `edge-controller.log` 和 `edge-web.log` 的版本行；
- controller 故障：查看 `/opt/edge-controller/VERSION`；
- 核对发布来源和构建时间：查看 `/opt/edge-controller/package-info.json`；
- 核对升级目标、结果和回滚状态：查看 `/opt/edge-controller/update/status.json` 及 `update.log`；
- 远程支持：导出诊断包并核对 `product/`、`logs/` 和 `manifest.json`。

正式发布保证根 `VERSION`、controller 编译版本、edge-web 编译版本、包名和 `package-info.json.version` 使用同一个版本事实源。
